# Job Finder, этап 1: сборщик удалённых IT-вакансий

Дата: 2026-11-22. Статус: черновик на проверку.

## 1. Цель и границы

Локальный инструмент для одного человека. Собирает удалённые IT-вакансии с 13 сайтов (русско- и англоязычных) в одну базу и показывает их на странице в браузере, где вакансию можно разобрать и отметить статусом.

Успех этапа:
- одна команда запускает сервер, страница открывается на `localhost`;
- сбор идёт сам каждые 6 часов и по кнопке;
- в ленте только удалёнка, доступная из Казахстана (весь мир, СНГ или список стран, где есть KZ), без дублей;
- у каждой вакансии видны название, компания, зарплата, требования, источник и ссылка на оригинал, есть кнопка «Найти отзывы о компании» и статусы;
- поломка одного сайта не мешает остальным и видна на экране «Источники».

Не входит в этап 1: ИИ, резюме, оценка совпадения (это этап 2), доска по статусам (вариант B), источники волны 2 (раздел 10), уведомления, мобильная версия сверх базовой адаптивности, многопользовательский режим.

## 2. Стек

- Python 3.12+ (на машине 3.14), окружение и запуск через `uv`.
- Сбор: `httpx` (HTTP), `feedparser` (RSS), `selectolax` (HTML), `json` для встроенных в страницу данных (`__NEXT_DATA__`, `__NUXT_DATA__`).
- Хранение: SQLite через стандартный `sqlite3`, один файл `data/jobs.db`; поиск FTS5 + `PyStemmer`.
- Сервер: FastAPI + Jinja2-шаблоны + HTMX для частичных обновлений, немного обычного JS для горячих клавиш.
- Расписание: APScheduler внутри процесса сервера.
- Тесты: `pytest`.
- Стиль страницы: дизайн-система qymyz.dev, ночная тема (цвета и шрифты переносятся в `static/style.css`).

## 3. Устройство

```
jobfinder/
  models.py        # Job — общий формат вакансии
  sources/
    base.py        # Source: name, lang, fetch(client) -> list[Job]
    hh.py habr.py getmatch.py hirify.py
    himalayas.py wwr.py remoteok.py jobicy.py workingnomads.py
    remotefirst.py arc.py rocketship.py hn.py
  normalize.py     # зарплата, грейд, стек, очистка HTML
  filters.py       # где можно работать, стоп-слова, IT
  dedup.py         # склейка дублей
  db.py            # схема и запросы
  search.py        # FTS5 + стемминг + синонимы
  synonyms.toml
  archive.py       # архив и чистка raw
  collector.py     # прогон источников, запись в runs
  scheduler.py
  web/ app.py templates/ static/
  cli.py           # jobfinder serve | collect [--source X] | check-sources | reparse
config.toml        # настройки пользователя
```

Каждый источник — отдельный модуль с одинаковым интерфейсом. Новый источник = новый файл и строка в реестре, остальной код не меняется.

Поток данных: источник → `Job` → нормализация → фильтры → склейка дублей → база → страница.

## 4. Общий формат вакансии (`Job`)

| Поле | Что хранит |
|---|---|
| `source`, `source_id`, `url` | откуда, id на сайте, ссылка на оригинал |
| `title`, `company` | название, компания |
| `salary_min`, `salary_max`, `salary_currency`, `salary_period`, `salary_raw` | зарплата разобранная и исходной строкой; период: месяц, год, час |
| `location_raw` | что написал сайт про локацию, как есть |
| `remote_scope` | `worldwide`, `cis`, `countries`, `restricted`, `unknown` (раздел 5) |
| `countries` | список стран, если сайт его дал |
| `timezones` | ограничения по часовым поясам, если есть |
| `seniority` | junior, middle, senior, lead или пусто |
| `stack` | список технологий (теги сайта, иначе поиск по словарю в тексте) |
| `lang` | `ru` или `en` |
| `description_html`, `description_text` | полный текст вакансии |
| `published_at`, `fetched_at` | когда опубликована, когда собрана |

## 5. Фильтры

**Где можно работать.** Страна пользователя задаётся в `config.toml` (`country = "KZ"`, `regions = ["worldwide", "cis"]`).
1. Сначала берём структурные поля сайта: Himalayas `locationRestrictions`, Arc.dev `requiredCountries` (пусто — весь мир), WWR `region`, RemoteOK `location`, Jobicy `jobGeo`, Working Nomads `location`, Remote Rocketship `location`.
2. Если полей нет, смотрим текст по словарю фраз: «US only», «USA only», «must reside in», «EU only», «только РФ», «гражданство РФ» и т.п. — `restricted`; «worldwide», «anywhere», «весь мир», «любая страна» — `worldwide`; «СНГ», «Казахстан», «CIS» — `cis`.
3. Показываем `worldwide`, `cis`, `countries` со страной пользователя. `unknown` тоже показываем, но с пометкой «уточнить». `restricted` скрываем.

**Формат.** Офис и гибрид отсекаются (у русскоязычных сайтов по их полю формата, у остальных по словам «hybrid», «on-site», «гибрид», «офис»).

**IT.** Почти все источники IT-only. Там, где нет, берём только IT-категории (hh: профессиональные роли IT; Remote First Jobs: ленты разработки, DevOps, данных, QA).

**Стоп-слова** из настроек (например «1С», «PHP») скрывают вакансию.

Скрытые фильтром вакансии не удаляются: у них заполнено `hidden_reason`, и они видны в разделе «Скрытые» с причиной, чтобы проверить, что фильтр не врёт.

## 6. Склейка дублей

Ключ: нормализованные компания + название (нижний регистр, без знаков, без слов «remote», «удалённо», грейда в скобках). Совпадение ключа в пределах 30 дней — одна вакансия со списком ссылок на все сайты. Основной текст берём у источника с самым полным описанием.

## 7. База и хранение

- `jobs` — одна строка на вакансию после склейки, все поля `Job`, `dedup_key`, `first_seen_at`, `last_seen_at`, `archived_at`, `hidden_reason`.
- `postings` — `job_id`, `source`, `source_id`, `url`, `first_seen_at`, `last_seen_at`, `raw` (исходный ответ сайта по этой вакансии, сжатый zlib): где опубликована.
- `jobs_fts` — полнотекстовый индекс FTS5 по названию, компании, стеку и тексту (раздел 9а).

Ничего не удаляется при новом сборе: известные вакансии обновляются (последняя версия полей, `last_seen_at`), новые добавляются.

**Архив.** Вакансия получает `archived_at`, если её не видели ни в одном источнике 7 дней, и при этом каждый её источник за эти дни хотя бы раз собрался успешно (упавший сайт не отправляет в архив всё подряд). Если вакансия снова появилась — `archived_at` снимается.

**Чистка.** Раз в сутки: у вакансий в архиве дольше 90 дней, у которых статус `new` или `seen` (пользователь их не отмечал), удаляется `raw`; поля и текст остаются. Вакансии со статусами `interesting`, `applied`, `rejected` хранятся целиком. Срок 90 дней — в настройках.

**Повторный разбор.** Команда `jobfinder reparse [--source X]` заново разбирает сохранённые `raw` текущими парсерами без запросов к сайтам.
- `user_status` — `job_id`, `status` (`new`, `seen`, `interesting`, `applied`, `rejected`), `updated_at`. Отдельно от вакансий, повторный сбор её не трогает.
- `runs` — `source`, `started_at`, `finished_at`, `ok`, `fetched`, `new`, `error`.

## 8. Сбор

Порядок: фильтр на стороне сайта → только новое → наш фильтр → подробности только по новым.
1. **Фильтр в запросе.** Каждый источник запрашивает у сайта только удалёнку и IT (и «весь мир», где сайт умеет). Сайты целиком не выкачиваются.
2. **Только новое.** Списки идут по дате; листаем, пока не встретим вакансию, которая уже есть в базе, и останавливаемся. Предел страниц на источник за сбор — в настройках источника (по умолчанию 5).
3. **Наш фильтр** (раздел 5) — для того, что сайт отфильтровать не умеет.
4. **Подробности.** Если список отдаёт только кусок текста, страница вакансии запрашивается только для новых вакансий, прошедших фильтр.

Ожидаемая нагрузка: 40–80 запросов за сбор на все источники, 3–10 на сайт.

Защита от блокировок:
- запросы к одному сайту строго по одному, пауза 1–2 с;
- ответ 429 или 403 — источник прекращает запросы до следующего сбора, в `runs` пишется причина;
- официальный API или RSS предпочитается разбору страниц; robots.txt соблюдается (исключение — Getmatch, см. ниже).

- У каждого источника таймаут 30 с и 2 повтора с паузой (кроме 429/403). Ошибка источника пишется в `runs` и не останавливает остальные.
- User-Agent: общий, без личных данных.
- Частота: каждые 6 часов. HN «Who is hiring» — раз в сутки проверяется, вышла ли новая ветка месяца.
- **hh.ru:** если в `config.toml` есть токен приложения с dev.hh.ru — официальный API (`schedule=remote`, IT-роли); если нет — разбор страницы поиска с теми же фильтрами.
- **Hirify:** только страницы с фильтрами (удалёнка + язык + специализация), без листания страниц: листание запрещено в robots.txt. Несколько запросов по специализациям.
- **Getmatch:** robots.txt запрещает `/api/`, пользователь принял риск для личного использования; пара запросов за сбор.
- **Arc.dev, Remote Rocketship, Hirify:** данные из встроенного в страницу JSON, официального API нет. При смене вёрстки источник падает с понятной ошибкой «формат страницы изменился».
- **RemoteOK, Remote First Jobs, Jobicy:** у каждой вакансии видна ссылка на оригинал (их условие).

## 9а. Поиск

Поиск идёт по своей базе, без запросов к сайтам и без ИИ.
- **Полнотекстовый:** SQLite FTS5. Перед индексацией и в запросе слова приводятся к основе стеммером Snowball (`PyStemmer`) для русского и английского: «разработчик» находит «разработчика», «developers» находит «developer».
- **Синонимы:** словарь в `jobfinder/synonyms.toml` раскрывает запрос: js = javascript, k8s = kubernetes, golang = go = голанг, senior = старший = ведущий, middle = мидл, junior = джун = младший и т.п.
- **Фильтры по полям** складываются с текстовым поиском: стек, зарплата от (с пересчётом валют по фиксированным курсам из настроек), грейд, язык, источник, свежесть, где можно работать.
- Смысловой поиск — этап 2.

## 9. Страница

Три экрана, по макетам на холсте Claude (варианты A, C, D):
- **Вакансии (A):** слева фильтры (поиск, источники, где можно работать, язык RU/EN, зарплата от, свежесть — по умолчанию 3 дня), в центре список, справа вакансия целиком. Разделы: **Лента** (активные и свежие, без отклонённых), **Мои** (`interesting`, `applied`, независимо от свежести и архива), **Архив**, **Скрытые** (отклонённые мной и отсечённые фильтром, с причиной). Открытие новой вакансии ставит ей «посмотрел».
- **Разбор (C):** новые вакансии по одной, клавиши ← не подходит, ↓ позже (= «посмотрел»), → интересно. Счётчик «12 из 47».
- **Источники (D):** таблица источников со статусом последнего сбора, ошибкой и числом новых; включение и выключение; кнопка «Обновить все»; настройки (частота, стоп-слова, токен hh).
- **Найти отзывы о компании:** выпадающий список ссылок-поисков по названию компании (Glassdoor, Dreamjob, Хабр Карьера, Google, Reddit). Сами отзывы не парсим.

## 10. Волна 2 (после запуска, отдельным ТЗ)

Stapply (ежедневная выгрузка вакансий с карьерных страниц компаний; нужно решить: качать файлы по 30–150 МБ или читать выборочно), прямой опрос Workable / Recruitee / SmartRecruiters по спискам компаний, JobSignal, DOU (с отсевом «только Украина»), CryptoJobsList, Geekjob, отдельные Telegram-каналы с разбором через ИИ.

## 11. Ошибки

- Сайт недоступен, ответ не тот, формат изменился — ошибка в `runs`, на экране «Источники» источник красный с текстом ошибки, остальное работает.
- Вакансия без обязательных полей (`title`, `url`) пропускается и считается в `runs`.
- Зарплату или локацию не удалось разобрать — сохраняется исходная строка, поле пустое, вакансия не теряется.

## 12. Тесты

- На каждый источник — сохранённый реальный ответ сайта (фикстура) и тест разбора без сети.
- Фильтры и склейка — табличные тесты на реальных строках локаций и названий.
- Поиск: формы слов и синонимы находят нужные вакансии. Архив: правило 7 дней не срабатывает при упавшем источнике; чистка не трогает отмеченные вакансии.
- Дым-тест страницы: сервер поднимается, три экрана отдают 200, смена статуса сохраняется.
- Живые запросы только командой `jobfinder check-sources`, не в тестах.

## 13. Запуск

```
uv sync
uv run jobfinder serve        # http://localhost:8000, сбор по расписанию
uv run jobfinder collect      # разовый сбор из консоли
uv run jobfinder reparse      # заново разобрать сохранённые ответы сайтов
```
